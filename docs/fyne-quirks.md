# Fyne quirks this module works around

Each entry has four parts: the Fyne behaviour, the version it was seen in, the
correction this module makes, and the canary test.

The canary test fails when Fyne changes the behaviour. A failed canary does not
mean this module is defective; it means you can examine the correction again.

The behaviour is that of `fyne.io/fyne/v2 v2.8.1` unless an entry gives a
different version. A row that shows "planned" does not have a test yet.

This document is written in plain technical English; see [How this is
written](style.md).

| # | Quirk | Workaround | Canary |
|---|---|---|---|
| 1 | File and folder dialogs fail if you call `Resize` before `Show`. The dialog does not have a window yet, so `Resize` asks a nil pointer for the minimum size. | `dialogs` calls `Show` first, then resizes the dialog to 760 x 520. | `TestChooserResizeAfterShowDoesNotPanic` (planned) |
| 2 | `widget.Check.SetChecked`, and the other setters a program calls, send `OnChanged`. | Form models hold a `setting` guard against re-entry, and list rows clear `OnChanged` before they call `SetChecked`. | `TestSetCheckedFiresOnChanged` (planned) |
| 3 | `SetText` on a table cell that is in use again refreshes the label, and the refresh is where `Importance` becomes a colour. If you set the importance after the text, the cell shows the colour of the previous row. | `table` sets `Importance` before it calls `SetText`. | `table.TestImportanceAfterSetTextKeepsOldColour` |
| 4 | `widget.Table.UpdateHeader` receives `Col == -1` for the corner cell. | `table` tests for this value. | `table.TestUpdateHeaderVisitsCornerCell` |
| 5 | `container.AppTabs` takes the height of its tallest item, not of the selected item. | Only the selected tab holds content. The other tabs hold an empty container. | `TestAppTabsSizeToTallestItem` (planned) |
| 6 | `widget.NewRichTextFromMarkdown` puts code blocks in a horizontal scroller (`richCodeBlock`). The innermost scroller below the pointer receives the wheel, and the scroller changes axis when the block is wider than the pane but not taller. | `markdown.CodePanel` draws code blocks itself, and wraps the text instead of scrolling it. | `fynetest.TestFyneStillDrawsMarkdownCodeInsideAScroll` |
| 7 | `widget.RichText` puts every segment in position and paints it again at each refresh, and a scroller refreshes its content while it moves. A document with 250 segments needs approximately 51 ms for each frame in the software painter. | `markdown.Pane` draws one block at a time, and only near the viewport. It keeps the measured height of each block. | `markdown.TestDocumentRendersOnlyNearTheViewport` |
| 8 | A theme icon made with `theme.XxxIcon()` before `app.New` writes the message "Attempt to access current Fyne app when none is started". | Section icons are a `func() fyne.Resource`, which the shell calls after the app exists. | `shell.TestNamesNeedNoApp` |
| 9 | Fyne animates properties, not opacity. A widget does not have an alpha value. | The banner fades the colour of its background rectangle with `canvas.NewColorRGBAAnimation`. | none (design, not a bug) |
| 10 | `widget.List` has no scroll callback, so a program cannot know that the user scrolled. | Follow-tail compares the current offset with the offset that the last automatic scroll left, to a tolerance of 4. | `TestFollowTailToleratesFractionalOffsets` (planned) |
| 11 | `fyne.Do` runs inline under the test driver, so a worker that touches widgets races the test. | The shell runs work inline when the window is not on screen. | `shell.TestPerformRunsInlineWhenHeadless` |
| 12 | Fyne ignores fontconfig and does not have a font chooser. | `theme` examines the font directories and loads the faces itself. | none |
| 13 | There is no interface scale API for one program; there is only `FYNE_SCALE`. | The shell writes the scale preference into the environment after `app.New` and before it makes the window. A restart applies the new value. | `TestScalePreferenceYieldsToEnvironment` (planned) |
| 14 | `fyne.Window` has no resize callback. Fyne tells a `CanvasObject` its own new size, so a widget around the object that needs the size is where to read it. | A program that keeps its geometry examines the size every 500 ms. `logpane` puts a widget around its list and lays the list out again in `Resize`. | `logpane.TestThePaneReflowsWhenTheWindowIsResized` |
| 15 | The GLFW Wayland backend does not have `cursor-shape-v1`, so a native Wayland window shows the default cursor theme. | `theme.ApplyCursorTheme` reads the desktop configuration and sets `XCURSOR_THEME` and `XCURSOR_SIZE` before the toolkit starts. Linux only. | none (needs a compositor) |
| 16 | `Border` gives its centre the space that is left, so a long label in the centre covers the objects beside it. | The status bar is an `HBox` in sequence, with a spacer. | none (layout rule) |
| 17 | An `HBox` gives a label its minimum size, and the minimum size of a label that truncates is zero. | Set the width of the label with `FixedWidth`. | none (layout rule) |
| 18 | There is no file dialog that selects more than one file. | "Add..." opens the single-file chooser again. | none |
| 19 | A glyph that the bundled font does not have, such as the right arrow `→`, draws from a fallback face. Fyne then marks the end of the run as a missing glyph. | Do not put these symbols in a label. Use words or theme icons. The up and down arrows `↑` `↓` are in the font, and sort headers use them. | none (copy rule) |
| 20 | `widget.Table` does not report a double tap. | Row actions are buttons that the selection enables. | none |
| 21 | Fyne cannot resolve a relative image path in Markdown while it runs, because the image segment needs a URI. | `markdown.Pane` reads an image that is a whole block from `Options.FS`. | `markdown.TestRelativeImagesResolveThroughTheFS` |
| 22 | `widget.NewRichTextFromMarkdown` draws a pipe table as a `TableSegment` in a scroller, and that scroller receives the wheel in the same way a code block does. | `markdown.Pane` draws a pipe table as a grid of cells, and renders the inline Markdown in each cell. | `markdown.TestFyneStillDrawsMarkdownTablesInsideAScroll` |
| 23 | There is no tooltip, and `desktop.Hoverable` exists but nothing uses it. Guidance that does not fit in the label of a control therefore has nowhere to go except below it, and that makes a row into a paragraph. | `widgets.WithTip` puts a transparent hover catcher over the control. | `widgets.TestATipWaitsAndThenAppears` |
| 24 | A pointer event goes to the **last** object that matches in the walk of the visible tree, not the first. `FindObjectAtPositionMatching` assigns the result at every match and does not stop. An object above another object therefore receives the hover, and a widget that only contains a control never receives one. | `widgets.WithTip` depends on this. The catcher is above the control, so it receives the hover, and it is not `Tappable`, so a tap continues past it to the control. | `widgets.TestFyneStillGivesAPointerEventToTheLastMatch` |
| 25 | A `canvas.Rectangle` with a nil fill colour is invisible in the GL painter, and is a nil dereference in the software painter. A window that contains one works on screen and cannot render to an image. | Spacers and hover catchers use `color.Transparent`. | `widgets.TestTheSpacersRenderToAnImage`, `widgets.TestATipRendersToAnImage` |
| 26 | **An overlay receives every pointer event in the window.** When an overlay is present, `FindObjectAtPositionMatching` examines the overlay instead of the content, so you cannot click anything below it at any screen position. A non-modal `widget.PopUp` puts itself in an `OverlayContainer`. That container is tappable and closes when you tap it, so the overlay uses the click instead of ignoring it. A control that showed its own tip needed two clicks, and the first click only removed the tip. | Tips and result banners are drawn in layers in the content of the window (`widgets.NewTipLayer` and the shell's `flashLayout`), not in overlays. The objects in those layers are not tappable, so the same walk finds the control below them. The dismiss button of a banner is tappable, and it still receives the clicks that are aimed at it. Only the busy popup is an overlay, because it is there to stop input. | `widgets.TestFyneStillSendsEveryClickToTheTopOverlay`, `widgets.TestAControlStillTakesItsClickWhileItsTipIsShowing`, `shell.TestABannerDoesNotTakeTheWindowsClicks` |
| 27 | Fyne does not tell a control that you clicked it instead of hovering over it. A hover tip therefore stays on screen when the click opens a menu or a dialog. The pointer does not leave the control, and while the new overlay is present the catcher of the tip receives no more mouse events (quirk 26). | `widgets.HideTips` removes every tip, both the tips on screen and the tips that wait. The shape menu of the shell and every dialog in `dialogs` call it before they open. | `widgets.TestATipComesDownWhenSomethingElseOpens`, `widgets.TestAWaitingTipIsCancelledWhenSomethingElseOpens` |
| 28 | `widget.List` uses again the widget it made for a row index, and does not call `UpdateItem` for that row. Content that changes while the number of rows stays the same is therefore not drawn again. `Refresh` adds the rows that are new and keeps the rows whose index existed before. `RefreshItem` reaches only a row that the layout lists as visible, which during a resize it may not. | `logpane` makes a new list when the wrapping changes. A list with no rows has nothing to use again, and the list is virtual, so the cost is the visible rows only. | `logpane.TestThePaneReflowsWhenTheWindowIsResized` |
| 29 | `CanvasObject.CreateRenderer` **makes** a renderer; it does not return the renderer that is in use. A walk that goes down through it reads a tree that was never on screen, such as a list with no rows or a scroller with no size. | Walk with `fynetest.WalkRendered`, `All` or `First`, which use the renderer in the cache. Code that looks for a structural object (`widgets.findTipLayer`) walks containers only, and does not call `CreateRenderer`. | `fynetest.TestAllFindsWhatWasDrawnRatherThanAFreshTree` |
| 30 | **A `widget.Label` shapes its text again each time it is resized**, through harfbuzz, if wrapping or truncation is on. That is how the label finds where to wrap or cut. `widget.Table` resizes every visible cell at every layout, so a window drag shapes the whole visible table again at every frame, for text that did not change. Measured on a catalog table with 7 columns: `RichText.updateRowBounds` used 42% of the CPU of the process, and the garbage collector behind it used 36% more. The window stopped for seconds at a time. `lineBounds` returns without measurement when wrapping and truncation are both off. | `table` draws cells and headers with both off, and cuts its own text to the column width with the rune metric that its column widths already use. A benchmark records the cost. | `table.BenchmarkResize` (738 µs before, 27 µs after) |
| 31 | **Fyne takes a stack traceback to find which goroutine it is on.** `async.IsMainGoroutine` reads the id from `runtime.Stack`, and `EnsureMain` calls it at every `Canvas.Refresh`, unless the program declares that it completed the `fyne.Do` migration. Measured during a window drag: 52% of the CPU of the process printed tracebacks. | This is not a correction in the library. A program that uses it must build with `-tags migrated_fynedo`, which is correct for this module because its components go to the UI thread with `fyne.Do`. Add the tag to your GUI build target. | none (a build flag, not code) |
| 32 | **A desktop window cannot be translucent.** The GLFW backend never sets `glfw.TransparentFramebuffer` and asks for no alpha bits. Only the wasm backend asks for `AlphaBits, 8` (`internal/driver/glfw/glfw_core.go`). A window cannot be see-through, and a widget has no alpha of its own (quirk 9). | A glance window is opaque by design. Contrast separates it from what is behind, and the compositor supplies the opacity of the whole window (`docs/glance.md`). | `TestFyneStillOffersNoTransparentFramebuffer` (planned) |
| 33 | **A program cannot read back the position of its window.** The GLFW position callback is connected inside Fyne (`SetPosCallback`), and nothing on `fyne.Window` gives the position. `desktop.Window.RequestPosition` writes only, and its own documentation says that the request can be ignored, "for example Linux Wayland". | There is no position to keep, so the program keeps none. A program that fixes the position of a glance window uses the desktop instead. On Plasma this is the KWin Scripting D-Bus API (`docs/glance.md`). | `TestFyneStillOffersNoWindowPosition` (planned) |
| 34 | **A window of fixed size grows to fit its content and never becomes smaller by itself.** `fitContent` only increases `requestedWidth` and `requestedHeight` (`if w.shouldWidth > w.requestedWidth`), so a window stays at its largest size after content is hidden. `Resize` assigns both values always, and it is the only way to make the window smaller. | A glance window calls `Resize(content.MinSize())` each time a card appears or disappears. | `glance.TestAHiddenCardShrinksTheWindow` |
| 35 | **Fyne reads a font that the theme does not have; it does not use a different font.** Bold text around a code span makes one segment that is bold and monospace. A theme without that face returns nothing from `Font`, and `painter.loadMeasureFont` reads the empty value. The theme of this module has the face and draws it. The **test** theme of Fyne does not, so every headless test of a document with an emphasised identifier fails. | `markdown.drawable` examines the style of each segment before the painter receives it. Where the theme has no face, it removes `Bold` and keeps `Monospace`. This depends on the theme, so a theme that has the face still draws it. | `markdown.TestFyneStillPanicsOnAFaceTheThemeDoesNotHave` |
| 36 | **A splash window takes the focus when it is shown.** Measured on Plasma 6 on Wayland with Fyne 2.8.1: after `Show`, `kdotool getactivewindow` named the splash window. Nothing on `fyne.Window` asks for a window that does not accept the focus. | `glance/kwin.Rule.NoFocus` writes `acceptfocus=false`, forced, and the compositor keeps the focus where it was. Without KWin the indicator takes the focus and the program says so in its documentation. | none (needs a compositor) |

## Adding an entry

Add the row, name the canary, and write the canary in the same commit as the
workaround. Bump Fyne in its own commit and run `make test`; a canary that
fails after the bump is the signal to remove its row and the code it guarded.
